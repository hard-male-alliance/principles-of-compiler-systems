\section{从汇编文本到进程映像}
\label{sec:elf}

\subsection{汇编：编码已知字节，记录未知地址}

本例的具体链路是作者书写的 \code{bounded\_factorial\_rv64gc.s} 到 \code{asm.rv64.o}。汇编器输入指令、标签和 \code{.text}/\code{.globl}/\code{.type} 等指示符，输出 ELF 可重定位对象（relocatable object）。指令已成为字节；同一节内的局部标签距离通常可立即求出，跨对象函数地址则仍未知。对象用节保存同类内容，用符号表描述定义与未定义名字，并用重定位项描述“链接时应如何修补某处”\cite{elf-gabi-2025,riscv-psabi-1.0}。

以 \code{main} 中 \code{call getint} 为例，汇编文本表达调用意图；对象中的符号表把 \code{main} 标为已定义全局函数、把 \code{getint} 标为未定义；重定位把调用位置、目标符号、类型和加数关联起来。本次 \code{asm.rv64.o} 在 \code{.text+0x2a} 实际同时出现 \code{R\_RISCV\_CALL\_PLT getint} 与 \code{R\_RISCV\_RELAX}：前者要求链接器解析调用目标，后者授权在最终距离已知后缩短序列。这里“未定义”不是错误，而是可重定位对象的正常开放义务。

\subsection{链接：把局部地址空间合成一个封闭程序}

链接器输入若干可重定位对象和归档库，先解析符号、选择所需成员，再合并输入节、安排地址并应用重定位，输出具有入口与程序头表的 ELF 文件\cite{lld-design-2026,elf-gabi-2025}。本例在此仅需说明：SysY 运行时库提供 \code{getint}、\code{putint} 和 \code{putch} 的外部定义；启动对象提供入口 \code{\_start}，它完成环境建立并最终调用 \code{main}。故操作系统入口不是 \code{main}。

静态链接把运行所需代码纳入文件。表~\ref{tab:sizes} 记录四条等价入口形态由文件系统 \code{stat} 得到的磁盘字节数。它不同于 \code{size} 所报告的 \code{text/data/bss/dec} 装载内容统计。C 与 SysY 源对象相差 8 字节，作者 IR 对象更小，作者汇编对象最小；静态文件之间只有数百字节差，而共同链接内容占主导。文件大小还受符号表、对齐、节和元数据影响，不能直接代表运行速度或“优化质量”。

链接松弛展示了为何链接器也能优化：汇编器面对未知全局布局只能发出可重定位的通用调用序列；链接器知道最终距离后，若 psABI 允许，可改成更短的编码。因此，对象反汇编和最终文件反汇编可能不同，即使源代码和 LLVM 优化都没有变化。

\subsection{加载：段而非节成为运行视图}

Linux 的 \code{execve} 用新程序映像替换当前进程。ELF 程序头表中的 \code{PT\_LOAD} 项给出文件范围、虚拟地址、内存大小、对齐与权限；若 \code{p\_memsz>p\_filesz}，尾部在内存中补零，这是未初始化数据的常见实现机制\cite{linux-elf-2026,linux-execve-2026}。内核准备初始栈与机器状态，然后把控制权交给 ELF 入口 \code{\_start}。

上一段描述的是目标机原生 Linux 的加载契约。本实验实际通过 QEMU 用户态模拟器（user-mode emulator）运行 RV64 文件：宿主先启动 \code{qemu-riscv64}，由它按来宾 ELF 建立来宾可见地址空间、翻译 RV64 指令，并把来宾系统调用转交宿主内核\cite{qemu-user-2026}。因此结果验证的是 RV64 Linux 用户态程序的可观察行为，不是 RISC-V 实机启动过程，更不能提供微架构性能证据。
