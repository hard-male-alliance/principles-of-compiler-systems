\section{研究对象与实验方法}
\label{sec:method}

\subsection{单一语义中心}

\texttt{preflight/src/compiler\_tour.sy} 是三种实现的共同规格。程序先把输入 $n$ 限制在 $[0,8]$，再用循环填充八元素局部数组；\texttt{sum} 遍历有效前缀，\texttt{fib} 递归计算小规模 Fibonacci 数。当且仅当 $n>2$ 时，表达式 \texttt{n > 2 \&\& mark()} 才调用带副作用的 \texttt{mark}，全局量 \texttt{ticks} 因而成为短路求值是否正确的可观察证据。限制输入同时消除了数组越界、递归爆炸与有符号整数溢出等混杂因素。

表~\ref{tab:cases}列出五个测试夹具。测试驱动将每个整数连同换行写入标准输入，逐字节比较标准输出并要求退出状态为零；只把 Windows 行尾统一为 LF，不删除其他空白。标准错误单独保存，因为 SysY 运行时析构器会输出计时信息。

\subsection{表示、环境与判定}

三份作者维护的表示分别是 SysY 源码、采用不透明指针（opaque pointer）的手写 LLVM IR，以及遵循 GNU 汇编语法的手写 RV64GC 程序。源码路径用 \texttt{-include} 强制载入 \path{preflight/include/sysy_builtin.h}，注入三个运行时函数的最小声明；它不修改 SysY 文件，也不包含存在缺陷的 \texttt{sylib.h}。权威 Linux 环境使用 Ubuntu Clang 18.1.3，交叉目标为 \path{riscv64-unknown-linux-gnu}，ISA/ABI 组合为 \texttt{rv64gc/lp64d}。最终静态 Linux ELF 由 \texttt{qemu-riscv64} 用户态执行；QEMU 在这里翻译 Linux 系统调用，而非模拟无操作系统的整机\cite{qemuUser}。

令 $P$ 为执行路径集合，$T$ 为五个夹具。路径 $p$ 的通过条件为
\begin{equation}
 \operatorname{pass}(p)=\bigwedge_{t\in T}
 \left(\operatorname{stdout}(p,t)=G_t \land \operatorname{exit}(p,t)=0\right),
\end{equation}
其中 $G_t$ 是版本库中直接编码的黄金输出。该判据验证测试域上的可观察等价而非所有输入上的形式等价；这一边界将在第~\ref{sec:threats}节讨论。

\subsection{流水线与证据层次}

构建系统以 CMake/Ninja 生成预处理文本、AST JSON、编译器生成 IR、RV64 汇编和三个 ELF64 小端 RISC-V 可重定位对象。结构检查直接读取 ELF 头并要求 \texttt{e\_machine=EM\_RISCV}，而非依据扩展名猜测格式。完整 Linux 流程再从 \texttt{lib/sylib.c} 重建运行时、链接三条 RV64 路径并执行测试。五项 CTest 分别覆盖 pipeline、advanced、optimization metrics、native 和 riscv；它们检验不同证据面，不能用一个“构建成功”互相替代。

实验还对同一源码、同一 Clang 18.1.3 和相同声明注入执行受控的 \texttt{-O0}/\texttt{-O2} IR 与 RV64 汇编对照。本文报告词法统计和可复核结构，不以静态计数推断运行时间。
