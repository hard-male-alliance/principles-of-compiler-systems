\begin{abstract}
编译系统不是把一段文本一次性“翻译”为机器码的黑箱，而是一条由表示、契约与工具共同构成的语义细化链。本文采用纵向实例研究，以一个长度有界的 SysY 整数截断点积为唯一主线，逐层追踪预处理记号、带类型抽象语法树、LLVM 中间表示、优化后的控制流与数据流、RV64GC 汇编、ELF 可重定位目标文件、静态链接映像以及 Linux 进程映像。案例同时覆盖数值运算、数组寻址、赋值、条件分支、循环、函数和 SysY 运行时调用；手写 LLVM IR 与手写 RISC-V 汇编通过同一组边界输入检验可观察行为。本文特别区分驱动程序展示的逻辑阶段与工具链实际启动的作业，区分优化产物中可观察的变化与对具体 Pass 的推断，并以符号、重定位及 ABI 解释“调用一个函数”如何跨越编译、汇编、链接和装载边界。实验还揭示了预编译 SysY RISC-V 归档与 Debian GNU/Linux C 运行环境之间的库 ABI 不匹配，由此说明“指令集相同”并不足以保证可链接。最后，以 MLIR 多方言和渐进式降低为中心，把 AscendNPU IR VecAdd 文档放回其实际抽象层级，并综述验证编译、翻译验证、等式饱和、反馈驱动优化、JIT/AOT 与可复现构建等方向。全文的核心结论是：理解编译器，关键不在背诵阶段名称，而在于识别每一层保存了什么语义、引入了什么约束，又把哪些决定推迟给下一层。

\keywords{编译系统 \and SysY \and LLVM IR \and RISC-V \and ELF \and MLIR \and 渐进式降低}
\end{abstract}
